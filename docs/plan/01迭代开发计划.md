## 一、总体策略

### 1.1 评估优先策略

采用「评估先行、执行后补」：阶段一以 `eval-only` 模式跑通评估链路（PackageBuilder 手动打包 → `agent-eval eval` 评估），评估体系验证成熟后再补 ExecutionAgent（DeepAgents 底座）实现 `agent-eval run` / `pipeline` 自动化执行。评估目标为 **Markdown/HTML 文档集**（不支持 PPTX）；评估统一由 **PipelineEngine** 执行（早期 EvaluationAgent 可选模式已于 2026-07-07 移除）。

## 四、风险与应对（持续生效项）

| 风险 | 应对 |
|------|------|
| deepagents/LangGraph 版本迭代快 | 锁版本 + `agent_eval/agent/` 适配层隔离；备选 Pydantic AI；Mock Agent 测试先行 |
| ExecutionAgent 成本失控 | BudgetController 双重限制（max_turns + max_budget_usd）；结构化日志实时 token 记录 |
| Agent 输出非结构化 | 强制 write_package Tool 写结构化包；AgentSession 记录全部 tool_calls |
| 多租户隔离越权 | 数据访问层强制 `org_id`/`project_id` 过滤；越权用例纳入集成测试 |
| 异构语言 schema 漂移 | 版本化 JSON 事件 schema 为唯一契约 + CI 校验；`schema_version` 不兼容显式拒绝 |
| 摄取可靠性丢数据 | 客户端持久化队列 + 重试 + 服务端 `event_id` 幂等；断网重放验证 |
| 对象存储 / DB 成本增长 | 项目级 `retention_days`；制品可仅留摘要；趋势物化视图降负载 |
