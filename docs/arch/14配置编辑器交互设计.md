# 配置编辑器交互设计：规则集 / 提示词 / 数据集统一编辑

> 本文档系统梳理 Web 配置中心三类资产编辑器（规则集、提示词、数据集）的现状、使用流程与相互关系，
> 基于实际发生的问题与行业最佳实践，给出统一的编辑器交互模型与分阶段落地方案。
> 属于 [13 配置管理设计](./13配置管理设计.md) 与 [09 Web 可观测平台架构设计](./09Web可观测平台架构设计.md) 在**前端编辑体验**层面的补充。

---

## 一、背景

配置中心的规则集（rule-sets）、提示词（prompts）、数据集（datasets）三类资产彼此引用：

- 规则集的每条规则通过 `prompt_id` / `confirmation_prompt_id` 绑定提示词，通过 `dataset_ids` 绑定参考数据集；
- 用户在编辑规则时，高频操作是「跳到被引用的提示词/数据集去编辑」「就地新建一个并绑定」。

因此**资产间的引用导航**是编辑器的核心流程，而非附加功能。当前实现存在两个并行编辑器，引用导航依赖
页面级跳转 + localStorage/sessionStorage 草稿接力，已在实际使用中暴露出多个缺陷（见 §三）。

---

## 二、现状梳理

### 2.1 两个并行编辑器

| | AssetEditor（独立资产编辑器） | PackageEditor（场景包编辑器） |
|---|---|---|
| 路由 | `/config/scenarios/:id/:kind/:assetId` | `/config/scenarios/:id/edit` |
| 入口 | ScenarioConfig 各表格行 / 行内「编辑」按钮 | ScenarioConfig 头部「进入包编辑器」、PackageWizard 创建后跳转 |
| 布局 | 单列编辑区 + 右侧版本时间线 | 左资产树 + 中编辑区 + 右版本时间线 |
| 多资产切换 | 页面级路由跳转（重挂载） | 树内 `selectAsset`（页内切换，不丢上下文） |
| 草稿 | localStorage `draft:{id}:{kind}:{assetId}`；仅 sessionStorage 往返标记时自动恢复 | 同一 key；任何草稿都提示可恢复 |
| 新建资产 | 先向服务端发布 0.1.0 骨架再跳转 | 纯本地内容，不发请求；但切走即丢、且无未保存提示 |
| 跨资产引用跳转 | `handleJumpAsset`：静默存规则草稿 → 路由跳转 → 返回时按 sessionStorage 标记恢复 | `onJumpAsset` = 树内选中（无草稿接力问题） |
| 额外能力 | 跨资产跳转/新建绑定、回链 | 聚合策略 / 指标定义编辑、完整度面板 |

**同一批表单组件（RuleSetForm/PromptForm/DatasetForm）被两个编辑器复用，但外围的导航、草稿、新建、发布语义各自实现且互相矛盾。**

### 2.2 引用关系与导航现状

```
ScenarioConfig（场景资产目录）
   ├── 行点击 ──────────────► AssetEditor（rule-sets/prompts/datasets）
   └── 「进入包编辑器」──────► PackageEditor

AssetEditor（规则集）
   ├── 跳转编辑提示词 ──► 存规则草稿(localStorage) + 置 sessionStorage 标记
   │                      ──► 路由跳转 AssetEditor(prompts)
   │                      ──► 「返回规则集」回链（location.state.from）
   │                      ──► 回到规则集：按标记恢复草稿
   └── 新建提示词 ──────► 生成 id → 写入规则字段 → 存草稿 → 服务端发布 0.1.0 骨架
                          ──► 跳转编辑 → 返回同上
```

### 2.3 当前用户主流程

1. 配置中心 → 场景 → 点击规则集 → 独立编辑器中编辑规则；
2. 在规则卡片中选择/跳转/新建提示词或数据集；
3. 保存草稿（localStorage）或发布新版本（不可变版本 + 标签）。

## 三、问题清单（均已在线上复现）

| # | 问题 | 根因 | 影响 |
|---|------|------|------|
| P1 | 规则集页误显「返回规则集 coursework-gate」 | 回链 state 随路由回跳残留在规则集页自身；未按 kind 过滤 | 界面错误信息，误导用户 |
| P2 | 打开规则页，评估方式/提示词变回「请选择」 | 加载时无差别自动恢复 localStorage 草稿，旧草稿覆盖已发布内容 | 已发布配置被污染显示，功能级故障 |
| P3 | 跳转提示词页空白崩溃 | 页面级跳转链路长（草稿接力 + state + 标记），任一环节异常即整页崩溃 | 用户无法编辑提示词 |
| P4 | 新建提示词即向服务端发布 0.1.0 骨架 | 为了让「跳转后可编辑」必须让资产先存在于服务端 | 版本历史被骨架污染；放弃编辑会留下垃圾资产 |
| P5 | PackageEditor 新建资产切走即丢且无提示 | 纯本地新建，无 dirty 标记、无草稿兜底 | 用户工作无声丢失 |
| P6 | 草稿共享 key 但两套恢复语义 | 两个编辑器各自实现草稿 | 在 A 存的草稿被 B 以不同规则恢复，行为不可预期 |
| P7 | 双编辑器功能重叠、入口分散 | 表格行进 AssetEditor、头部按钮进 PackageEditor，用户不知该用哪个 | 心智负担；同一资产两套编辑体验 |
| P8 | 无「新建规则集」入口 | 树中提示「先发布一个」但无按钮 | 新场景包无法自助创建规则集（功能死路） |
| P9 | 表单/YAML 切换、版本时间线、晋升、diff 双份实现 | 复制演进 | 修一处漏一处，持续发散 |

**共性根因**：缺少一个**以场景包为中心的单一编辑器**与**统一的草稿/新建/导航语义**；
页面级路由跳转被迫承担「上下文保持」职责，只能靠 localStorage/sessionStorage 打补丁，补丁又引入新 bug。

## 四、行业最佳实践参考

| 产品 | 可借鉴的模式 | 启示 |
|------|-------------|------|
| **VS Code** | 单编辑器 + 文件树 + Tab 多开；dirty 文件标题加圆点，「未保存」集中于编辑器状态而非隐藏存储；Peek Definition 就地查看引用 | 多资产 = Tab；引用查看不打断主编辑；dirty 可见性统一 |
| **Postman / Insomnia** | 左集合树 + 右 Tab 编辑区；请求间 `{{var}}` 引用即点即跳（树内定位） | 树是导航与归属的唯一事实源 |
| **Contentful / Sanity** | 内容间引用字段支持「就地编辑（drawer）」，保存后自动回到原表单上下文 | 引用编辑用抽屉/弹层，避免整页跳转 |
| **Figma** | 组件实例跳转主组件 = 画布内定位而非新开页面 | 跳转 = 同一工作区内定位 |
| **GitHub** | 文件浏览器与单文件编辑共用同一仓库视图；URL 即状态，可直接分享 | 编辑器状态应编码进 URL，刷新/分享不丢 |
| **Langfuse** | 配置对象列表 → 详情一体化，编辑为详情页内嵌表单，版本与草稿语义统一 | 查看与编辑同一页面，不搞两套入口 |

**共同原则**：
1. **一个工作区，一棵树，一套 Tab**——不允许两个平行编辑器并存；
2. **引用跳转 = 工作区内定位**（树内选中/新开 Tab），不打断当前编辑上下文；
3. **草稿显式可见、显式恢复**——永不静默覆盖已发布内容；
4. **URL 即状态**——当前选中资产编码进 URL，刷新/分享/浏览器前进后退天然正确；
5. **新建即草稿**——新建资产先以本地草稿存在，统一进入「待发布」列表，不向服务端发骨架版本。

## 五、目标交互模型

### 5.1 核心决策

**收敛为唯一编辑器：场景包编辑器（Package Editor）。** AssetEditor 退役为兼容重定向。

```
/config/scenarios/:id/edit?select=<kind>:<assetId>[&tab=form|yaml]
```

- 页面结构（沿用现有 PackageEditor 三栏）：**左资产树｜中编辑区（Tab 列表 + 表单/YAML）｜右版本时间线 + 完整度**；
- `select` 参数决定树中高亮与当前编辑对象——**URL 即状态**，刷新/分享/前进后退均正确；
- 旧路由 `/config/scenarios/:id/:kind/:assetId` 301 重定向到 `?select=` 形式（保留外链兼容）。

### 5.2 关键流程（目标态）

**A. 编辑规则 → 查看/编辑被引用提示词**

1. 规则卡片上点击提示词 chip（或「编辑」图标）；
2. 资产树定位并选中该提示词，**当前规则集编辑状态保留在 Tab 中**（不卸载、无需草稿接力）；
3. 编辑完成后切回规则集 Tab，上下文原样保留。

**B. 编辑规则 → 新建提示词并绑定**

1. 规则卡片点「新建」→ 资产树出现 `prompt_xxxx（未发布）` 节点并选中，**同时**把新 id 写入当前规则的 `prompt_id`；
2. 新资产是**本地草稿**（树中标记「未发布」），不向服务端发骨架版本；
3. 用户编辑内容后在提示词 Tab 单独发布，或随「批量发布」一起发布；
4. 规则集发布时校验：引用的资产必须已发布或在本批次内发布，否则阻塞并提示。

**C. 草稿语义（统一）**

- 每个资产至多一份草稿：`draft:{scenarioId}:{kind}:{assetId}`，内存态为唯一工作区状态，localStorage 仅作崩溃/刷新兜底；
- 切换资产**不丢**未保存内容（内存中保留每个 Tab 的编辑态），树节点与 Tab 标题显示 dirty 圆点；
- 刷新后进入编辑器：若存在草稿，树节点标「草稿」，点击后由用户**显式**选择「恢复草稿 / 使用已发布」——**绝不静默覆盖**；
- 发布后清除对应草稿。

**D. 创建规则集（补死路）**

- 资产树「规则集」分组提供「新建规则集」按钮，与提示词/数据集一致：本地草稿 + 预置最小骨架（version/scenario/一个空 cascade）。

### 5.3 编辑器状态机（每资产）

```
          ┌──────────┐  编辑内容   ┌──────────┐  发布成功   ┌────────────┐
 已发布 ─►│ clean    ├───────────►│ dirty    ├───────────►│ clean(新版本)│
          └──────────┘            └──────────┘             └────────────┘
               ▲                       │ 切 Tab：保留在内存
               │ 显式「放弃改动」        │ 刷新：落 localStorage 草稿
               └───────────────────────┘
```

## 六、详细方案

### 6.1 路由收敛

| 路由 | 去向 |
|------|------|
| `/config/scenarios/:id/edit` | 唯一编辑器（`select` query 参数指定选中资产） |
| `/config/scenarios/:id/:kind/:assetId` | 重定向 → `/edit?select=<kind>:<assetId>` |
| ScenarioConfig 表格行/编辑按钮 | 一律跳 `/edit?select=...` |
| 「进入包编辑器」按钮 | 跳 `/edit`（默认选中第一个规则集） |

### 6.2 组件结构

```
PackageEditorPage
├── AssetTree            左：规则集/提示词/数据集/策略 分组 + 新建按钮 + dirty/草稿/未发布标记
├── EditorTabs           中上：已打开资产 Tab（dirty 圆点、关闭按钮）
├── AssetFormHost        中：按 kind 渲染 RuleSetForm/PromptForm/DatasetForm/PolicyEditor/MetricDefsEditor
│                          + FormYamlToggle
├── VersionTimeline      右：版本时间线 + 发布新版本（Modal）+ 晋升/diff
└── CompletenessPanel    右下（规则集时）：完整度
```

- `AssetFormHost` 的 `content/dirty` 以 `select` 为 key 存入 **editor store（useReducer / zustand）**，实现切 Tab 不丢；
- RuleSetForm 的 `onJumpAsset` → `setSelect(kind:assetId)`（树内定位，开 Tab）；`onNewPromptForRule` → 创建草稿资产 + 写入引用字段 + `setSelect`；
- 删除 AssetEditor.tsx（保留重定向组件）；其跨资产跳转、sessionStorage 标记、回链逻辑**整体移除**。

### 6.3 统一草稿 Store

```
interface EditorState {
  selected: string | null                 // "kind:assetId"
  tabs: string[]
  docs: Record<string, { content: any; baselineYaml: string; dirty: boolean; isNew?: boolean }>
  drafts: Record<string, { savedAt: string }>   // localStorage 镜像，仅刷新后用于显式恢复
}
```

- 写路径：表单 onChange → docs[key]；防抖落 localStorage 草稿；
- 恢复路径：仅用户点击「恢复草稿」时把草稿灌入 docs；
- 发布路径：publish 成功 → 清 docs[key].dirty + 删草稿 + 若 isNew 则转正式节点。

### 6.4 新建与发布校验

- 新建资产 `isNew: true`，仅存在于 editor store（+草稿兜底），树中标记「未发布」；
- 发布规则集前校验引用完整性：`prompt_id` / `confirmation_prompt_id` / `dataset_ids` 引用的资产须满足「已发布 ∨ 当前 editor store 中存在」，缺失时列出并阻止发布；
- 提供「连同引用一起发布」批量操作（按依赖顺序发布）。

### 6.5 导航与回退

- 废弃 `location.state.from` 与「返回规则集」回链——**浏览器前进/后退即回退**（URL 即状态天然支持）；
- 资产树恒定可见，任何时刻可点击回原资产，不需要专用回链。

### 6.6 表单层复用与清理

- RuleSetForm / PromptForm / DatasetForm 继续复用；回调签名统一为：
  - `onSelectAsset(kind, assetId)`（替代 onJumpAsset）
  - `onCreateAsset(kind, bind?: { ruleIndex, field })`（替代 onNewPromptForRule / onNewDataset / onNewPrompt 三份签名）
- 删除 PackageEditor 旧 `newAsset`（本地即丢版）与 AssetEditor 全套逻辑。

## 七、分阶段落地计划

| 阶段 | 内容 | 收益 |
|------|------|------|
| **P0 止血（已完成）** | 修复回链自显（kind 过滤）、草稿恢复改为往返标记限定、PromptForm 防御式渲染 | 消除当前三个线上 bug |
| **P1 收敛** | URL `select` 化；AssetEditor 改重定向；ScenarioConfig 全部入口指向统一编辑器；统一草稿语义（显式恢复）；补「新建规则集」 | 双编辑器合一，草稿/导航语义唯一 |
| **P2 增强** | EditorTabs 多开；新建资产本地草稿化（去 0.1.0 骨架发布）；引用完整性发布校验 + 批量发布 | 引用编辑零跳转、零骨架污染 |
| **P3 打磨** | 提示词 Peek 抽屉（不离开规则页就地编辑）；未保存离开拦截；规则引用反查（哪些规则用了此提示词） | 体验对齐一线产品 |

> 说明：P0 中「往返标记恢复草稿」「location.state 回链」为过渡方案，P1 完成后随旧编辑器一并移除。

## 八、验收标准

1. 从任意入口进入编辑器，URL 含 `select`，刷新后选中资产与编辑内容（含未保存 dirty）状态正确；
2. 规则页跳转提示词 = 树内定位 + Tab 切换，全程无页面重挂载、无草稿接力、无专用回链；
3. 新建提示词自动绑定规则字段，树中显示「未发布」，不新增服务端骨架版本；规则集发布时对未发布引用给出阻塞提示；
4. 任何情况下已发布内容不会被草稿静默覆盖；草稿恢复必须经用户显式确认；
5. AssetEditor 旧路由访问自动重定向，外链不失效；
6. 新建场景包后可完整自助创建规则集 + 提示词 + 数据集并发布。
