# 评测配置与数据架构

> 本文档定义评测系统的**配置与数据架构**：概念模型、存储位置、维护方式与运行时数据流，作为开发实施的基准。属于 [01 整体架构设计](./01整体架构设计.md) 的数据维度展开；执行链路见 [03](./03执行引擎设计.md)，字段级规范见 [06](./06数据管理与配置规范.md)，场景包体系见 [13](./13配置管理设计.md)。

---

## 一、设计总览

### 1.1 两轴模型

一次评测运行是两个独立轴的绑定：

| 轴 | 回答 | 内容 | 变更节奏 | 维护方式 |
|----|------|------|---------|---------|
| **场景包** | 怎么评 + 问什么 | 评估方法论（规则/提示词/指标）+ 考卷（任务集） | 慢，随方法演进 | PR 评审 + 版本发布 |
| **SUT 注册表** | 问谁 | 被测系统接入（端点/协议形态/测试账号/modelId） | 快，随部署变更 | 每环境一份配置文件 |

设计依据（行业主流形态）：lm-evaluation-harness 的 task YAML 按套件目录组织并内嵌 dataset 引用、Inspect AI 的 eval 自包含目录——**考卷随场景打包分发，被测对象是运行参数**（`--model` / `--sut`）。

### 1.2 数据敏感分级

管理方式由敏感级别决定，而非「凡凭证皆密钥」：

| 级别 | 数据 | 管理方式 |
|------|------|---------|
| 🔴 真密钥 | LLM api_key（计费损失） | 本地 `~/.agent_eval/llm.json`（0600）；平台 DB 加密 + 拉取 |
| 🟡 测试账号 | SUT 登录用户名/密码/验证码（staging 测试账号，低敏） | **内联于 sut_config**，随配置版本化——不进 `.env`、不加密 |
| 🟠 运行时会话 | 登录后的 session token | `workspace/sut_sessions/`（0600），过期清理 |
| ⚪ 环境接入 | 平台地址、上报鉴权、基础设施连接 | `.env`（本地）/ SCF env（云端） |

`.env` 只承载环境接入，不承载任何业务配置。

### 1.3 数据全景

| 数据 | 轴/类别 | 位置 | 入库 | 说明 |
|------|---------|------|------|------|
| 场景包（规则/提示词/指标/数据集/任务集） | 场景包轴 | `evaluator/agent_eval/assets/packages/{scenario}/{ver}/` | ✅ | 版本+标签；DB 副本供云端 |
| SUT 注册表（含测试账号） | SUT 轴 | `evaluator/sut_systems/*.yaml` | ✅（开源时挪出主仓） | 仓库内、pip 包外 |
| LLM 角色注册表 | 工具配置 | `~/.agent_eval/llm.json` / 平台 `llm_models` | ❌ | 双形态（§2.3） |
| 运行产物/缓存/会话 | 运行时 | `workspace/` | ❌ | 见 §三 |
| 平台上报数据 | 输出 | 平台 PG + COS | — | 见 [09](./09Web可观测平台架构设计.md) |

## 二、配置与资产的维护

### 2.1 场景包（含任务集）

场景包是评测的分发单元，一个场景的全部评估定义打包在一起：

```
packages/{scenario}/{ver}/
├── agent_eval.yaml          # manifest：id/version/entry_points/default_rule_set/default_task_set
├── rules/                   # 怎么评：规则集（评估器绑定 + llm_role 角色）
├── prompts/                 # Judge 提示词（YAML 维护，不 hardcode）
├── metrics/                 # 指标定义 + 聚合策略（policy.yaml）
├── datasets/                # 参考知识（reference 数据）
├── task_sets/               # 问什么：考卷
│   ├── default.yaml         #   缺省考卷（manifest 的 default_task_set 指向）
│   └── regression.yaml
└── sut_configs/             # 预留：benchmark 裸模型（静态权重，GSM8K 类）
```

**任务集**（task 的 `input`/`expected`/`constraints`）内嵌于场景包——考题与规则的兼容性随包版本共同演进，schema 复用 `TaskSet`（`scenario` 字段对齐包归属）。

**维护与分发链路**：PR 评审入库 → 版本/标签（latest/production）→ `importAssetsToDb` 同步 DB 副本（`TaskSetAsset` 挂 scenario 级）→ 云端按 `名称@版本` 引用拉取。与既有场景包链路完全一致，无新机制。

**引用方式**：CLI `--package chat --task-set default`（包内名）；`--task-set <路径>` 显式外挂自定义考卷。

### 2.2 SUT 注册表

```yaml
# evaluator/sut_systems/sasan-agent@staging.yaml —— 每环境一份
sut:
  name: sasan-agent
  base_url: https://agent-server.staging.example.com
  protocol_flavor: commands
  auth:
    type: api_login
    credentials:              # 测试账号内联（低敏配置数据）
      username: "138xxxx0000"
      password: "330330"      # staging 固定验证码
    login: {...}
```

- **位置**：`evaluator/sut_systems/`——仓库内（入库评审）、pip 包外（真实端点不随 wheel 分发）；开源时该目录整体挪出主仓
- **账号内联**：测试账号是低敏测试数据，随配置走；`credential_ref`（env 引用）保留为可选覆盖，用于确属敏感的凭证
- **云端分发**：executor 镜像构建时 COPY `evaluator/` 自动携带注册表，不建 DB 通道
- **引用方式**：CLI `--sut sasan-agent@staging`；显式路径 `--sut-config <file|dir>` 覆盖

### 2.3 LLM 配置（双形态，已实施）

- **本地 CLI**：`agent-eval models login/list/test/logout` 交互向导 → `~/.agent_eval/llm.json`（0600）；三角色 `text`（评估文本，default）/ `vision`（视觉）/ `agent`（执行侧，回退 text）；规则集 `params.llm_role: vision` 绑定
- **云端**：平台 `/admin` 按角色配置（`llm_models.role`）；executor 经 `GET /api/public/llm-config`（API Key + 限流 + 审计）拉取——两套实现互不感知
- 解析统一入口 `config/llm_resolution.py`（本地文件优先 → 平台兜底）；详细规范见 [06 §4.8](./06数据管理与配置规范.md)

### 2.4 环境接入（`.env`）

`AGENT_EVAL_HOST/API_KEY/UPLOAD`（平台上报）、`PLATFORM_*`（web/executor 基础设施）、`WORKSPACE_DIR`。仅此——LLM 与 SUT 业务配置均不在 `.env`。

## 三、运行时数据与产物（workspace）

`workspace/` 是评测状态的单一聚集地——**清除 workspace 即获得全新重测环境**：

```
workspace/
├── runs/{run_id}/           # 一次运行的产物分层
│   ├── packages/{task_id}/  #   ExecutionPackage（manifest/task/trace/metrics + output/）
│   ├── agent_logs/          #   执行 Agent 决策日志（JSONL）
│   ├── results/{task}/      #   评估结果（report/rule_results/scores + evidence/）
│   └── reports/             #   汇总报告 + run_manifest
├── cache/                   # 评估缓存（键 = 内容指纹 + 规则集 + LLM 指纹）
├── packages/                # pack 命令的执行包输出
├── datasets/                # 本地数据集
└── sut_sessions/{sut}.json  # SUT 登录会话 token（0600，过期清理；跨 run 复用）
```

## 四、目录组织总览

```text
agent-eval-system/                        ← 仓库
├── evaluator/
│   ├── agent_eval/assets/                ← 随 pip 发布（进 wheel）
│   │   ├── packages/{scenario}/{ver}/    ←   场景包（含 task_sets/，§2.1）
│   │   ├── examples/                     ←   配置模板
│   │   └── schemas/                      ←   JSON Schema（公开契约）
│   └── sut_systems/                      ← SUT 注册表（仓库内、pip 包外，§2.2）
│
├── .env                                  ← 仅环境接入（§2.4）
│
workspace/                                ← 运行状态（§三）
~/.agent_eval/llm.json                    ← LLM 角色注册表（0600，§2.3）

平台 DB                                   ← 云端配置面
├── scenario_packages / *_assets          ←   场景包资产副本（importAssetsToDb 同步）
└── llm_models                            ←   云端 LLM 配置（api_key 加密）
```

## 五、一次评测运行的数据流

```text
输入绑定                     运行                        输出与上报
─────────                   ────                        ─────────
场景包（含考卷）──┐
                 ├→ 运行定义 ──→ 执行 Agent ──→ ExecutionPackage ──→ 评估器 ──→ 指标/报告
SUT 注册表 ────────┘    （run_manifest  （驱动 SUT、     （workspace/runs/      （LLM Judge 用
LLM 配置 ─────────────→  记录三者引用     会话复用、        /packages/）          角色注册表）
suite.yaml（可选）       与内容指纹）     预算控制）              ├→ 本地报告
                                                              └→ ResultSink → 平台（events + 制品）
```

- **运行定义显式化**：`run_manifest` 记录 `{package_ref(含 task_set), sut_ref, llm 指纹}` 与内容指纹——可复现、可对比、可审计；`Run.sutVersion` 与事件 `sut_version` 随之填充
- **suite.yaml 声明式矩阵**（不同考卷 × 不同环境的批量对照）：

```yaml
suite: sasan-agent-monthly
runs:
  - { package: chat@1.0, task_set: default,    sut: sasan-agent@staging }
  - { package: chat@1.0, task_set: regression, sut: sasan-agent@staging }
  - { package: chat@1.0, task_set: default,    sut: sasan-agent@prod }
```

## 六、实施指引（现状 → 目标）

已实施：LLM 配置双形态（§2.3）。其余为目标态，按优先级：

| 优先级 | 实施项 | 内容与验收 |
|--------|--------|-----------|
| P0 | 任务集并入场景包 | `workspace/task_sets/` 按场景归位到包内 `task_sets/`；manifest 增 `default_task_set`；CLI 支持包内名引用；`TaskSetAsset` 随包同步（scenario 级） |
| P0 | SUT 注册表迁入 + 账号内联 | `workspace/sut_configs/` → `evaluator/sut_systems/`；`auth.credentials` 内联支持（`credential_ref` 降为可选覆盖）；`CredentialStore` 读取内联值 |
| P0 | 会话目录迁移 | `~/.agent_eval/sut_sessions/` → `workspace/sut_sessions/`（0600 语义不变） |
| P0 | 运行绑定显式化 + suite | `run_manifest` 三元组 + 指纹；`Run.sutVersion`/`sut_version` 填充；`agent-eval suite` 命令（矩阵展开 + 汇总对照） |
| P1 | 执行包归位 run_id | `run` 产物写 `runs/{run_id}/packages/{task_id}/`，manifest 登记；`--package-dir` 接受 run 目录 |
| P1 | SUTConfigAsset 表移除 | 无消费方的预留表删除（schema + 迁移） |
| P2 | 执行包内容指纹 / workspace 分区 | 缓存键恢复内容维度；根目录收敛为 `runs/ cache/ packages/ datasets/ sut_sessions/` |
| P3 | 远端数据地图 | Langfuse / 平台 / 本地各自承载的数据、保留期、导出方式成文 |
