# 评测配置与数据架构

> 本文档定义评测系统的**配置与数据架构**：概念模型、存储位置、维护方式与运行时数据流，作为开发实施的基准。属于 [01 整体架构设计](./01整体架构设计.md) 的数据维度展开；执行链路见 [03](./03执行引擎设计.md)，字段级规范见 [06](./06数据管理与配置规范.md)，场景包体系见 [13](./13配置管理设计.md)。

---

## 一、设计总览

### 1.1 场景包模型（单轴 + 运行时覆盖）

**场景包是评测的组织中心**——一个场景的全部定义打包在一起：

| 包内目录 | 回答 | 内容 | 变更节奏 |
|----------|------|------|---------|
| `rules/` `prompts/` `metrics/` | 怎么评 | 评估方法论（规则/提示词/指标） | 慢，PR 评审 |
| `task_sets/` | 问什么 | 考卷（任务集） | 随评测内容演进 |
| `sut_configs/` | 问谁 | 被测系统接入（端点/协议/modelId，**不含凭证**） | 随部署变更 |

一次评测运行 = 一个场景包引用；考卷与被测系统默认从包内解析，显式参数（`--task-set <路径>` / `--sut-config <路径>`）可覆盖——覆盖能力对齐 `--include_path` 惯例。多环境/多实例经包内多文件 + `--sut <名>` 选择表达。

设计依据：考卷与被测系统接入随场景内聚（promptfoo 的 providers+tests 同文件即此形态）；被测对象的地址与实例是运行时选择，不是独立维护的注册表。

### 1.2 数据敏感分级

管理方式由敏感级别决定，而非「凡凭证皆密钥」：

| 级别 | 数据 | 管理方式 |
|------|------|---------|
| 🔴 真密钥 | LLM api_key；SUT 登录账号（用户名/密码/验证码） | 本地 `~/.agent_eval/`（0600：`llm.json` + `sut_credentials.json`）；云端平台页面（加密存储 + 鉴权拉取）——**不入包、不入 `.env`** |
| 🟠 运行时会话 | 登录后的 session token | `workspace/sut_sessions/`（0600），过期清理 |
| ⚪ 配置数据 | SUT 端点/协议/modelId；场景包全部内容 | 随包 YAML，入库评审（内部仓即私有） |
| ⚪ 环境接入 | 平台地址、上报鉴权 | `.env`（本地）/ SCF env（云端） |

`.env` 只承载环境接入，不承载任何业务配置与凭证。

### 1.3 数据全景

| 数据 | 位置 | 入库 | 说明 |
|------|------|------|------|
| 场景包（方法论+考卷+SUT 接入配置） | `evaluator/agent_eval/assets/packages/{scenario}/{ver}/` | ✅ | 版本+标签；DB 副本供云端；开源包 `sut_configs/` 留空 |
| LLM 角色注册表 | `~/.agent_eval/llm.json` / 平台 `llm_models` | ❌ | 双形态（§2.3） |
| SUT 凭证 | `~/.agent_eval/sut_credentials.json` / 平台 Secrets | ❌ | 双形态（§2.2/§2.4） |
| 运行产物/缓存/会话 | `workspace/` | ❌ | 见 §三 |
| 平台上报数据 | 平台 PG + COS | — | 见 [09](./09Web可观测平台架构设计.md) |

## 二、配置与资产的维护

### 2.1 场景包（评测的组织中心）

```
packages/{scenario}/{ver}/
├── agent_eval.yaml          # manifest：id/version/entry_points/
│                            #   default_rule_set / default_task_set / default_sut
├── rules/                   # 怎么评：规则集（评估器绑定 + llm_role 角色）
├── prompts/                 # Judge 提示词（YAML 维护，不 hardcode）
├── metrics/                 # 指标定义 + 聚合策略（policy.yaml）
├── datasets/                # 参考知识（reference 数据）
├── task_sets/               # 问什么：考卷
│   ├── default.yaml         #   缺省考卷（manifest 的 default_task_set 指向）
│   └── regression.yaml
└── sut_configs/             # 问谁：被测系统接入（不含凭证；eval_only 型场景无此目录）
    ├── sasan-agent@staging.yaml   # 多系统=多文件（SUTRegistry.load_dir 语义）
    └── sasan-agent@prod.yaml      # 多环境=文件名后缀；--sut <名> 选择
```

- **任务集**内嵌场景包：考题与规则的兼容性随包版本共同演进（schema 复用 `TaskSet`）
- **SUT 接入配置**内嵌场景包：端点/协议/modelId 属低敏配置数据，随包入库（内部仓即私有）；开源场景包该目录留空（用户可写区）
- **维护与分发链路**：PR 评审入库 → 版本/标签 → `importAssetsToDb` 同步 DB 副本（含 `TaskSetAsset`，scenario 级）→ 云端按 `名称@版本` 引用拉取——一条链路承载全部包资产
- **运行**：`agent-eval run --package chat`——考卷与 SUT 全从包内解析（唯一 SUT 自动选中；`--task-set`/`--sut-config` 显式路径覆盖）

### 2.2 SUT 凭证（双形态）

配置与凭证彻底分离：包内 `sut_configs/` 只存端点与协议，凭证经 `credential_ref` 引用到独立的凭证区。

**本地（CLI）**——通用 KV 交互录入 + 0600 文件（`secrets` 子命令组，不绑定特定凭证形态）：

```bash
$ agent-eval secrets set sasan.username     # 任意 <ref>.<field>，字段名自由
? 值: ••••••                                # 隐藏输入
✅ 已保存 ~/.agent_eval/sut_credentials.json（0600）

$ agent-eval secrets set sasan.token        # static_token 型；api_login 型则 username/password
$ agent-eval secrets list                   # 已设 ref.field 清单（不显值）
$ agent-eval secrets delete sasan.password
```

`~/.agent_eval/sut_credentials.json`：`{"sasan": {"username": "...", "token": "..."}}`（`ref → {field: value}` 通用结构，字段名不受限）——与 `llm.json` 同目录同惯例，`~/.agent_eval/` 即**本机密钥区**；与云端 Secrets 的通用 KV 模式对称。

**读取链**（`CredentialStore`，本地文件 → 环境变量兜底）：

```
sut_credentials.json（本地，secrets set 录入）
        ↓ 未命中
进程 env（AGENT_EVAL_SUT__<REF>__{USERNAME|PASSWORD|TOKEN}，云端注入）
        ↓ 未命中
报错并引导 secrets set
```

### 2.3 LLM 配置（双形态，已实施）

- **本地 CLI**：`agent-eval models login/list/test/logout` → `~/.agent_eval/llm.json`（0600）；三角色 `text`（评估文本，default）/ `vision`（视觉）/ `agent`（执行侧，回退 text）；规则集 `params.llm_role: vision` 绑定
- **云端**：平台 `/admin` 按角色配置（`llm_models.role`）；executor 经 `GET /api/public/llm-config`（API Key + 限流 + 审计）拉取——两套实现互不感知
- 解析统一入口 `config/llm_resolution.py`；详细规范见 [06 §4.8](./06数据管理与配置规范.md)

### 2.4 平台 Secrets（云端凭证面，GitHub Secrets 式）

云端 executor 无状态、无交互入口——一切 env 型秘密（SUT 凭证等）经平台页面配置：

- **存储**：`secrets` 表（org 级通用 KV：`name` 唯一 + `valueEncrypted`，AES-256-GCM 复用 `PLATFORM_KEY_ENCRYPTION_KEY` 设施）
- **页面**：org 设置「Secrets」卡片——新增/覆盖（password 输入框）/删除；列表只显示名称与最后修改时间，**值写后不可读**（对齐 GitHub Secrets）
- **拉取**：`GET /api/public/secrets`（Bearer API Key → org，解密返回 KV，审计打点）——与 `/api/public/llm-config` 同款模式
- **注入**：executor 启动时拉取 → 注入 `os.environ` → `CredentialStore` 的 env 通道**零改动**读到

云端维护入口由此收敛：业务配置与凭证全部在平台页面（`/admin` LLM + org Secrets）；SCF 控制台只剩引导性环境接入（`AGENT_EVAL_HOST/API_KEY`）。

### 2.5 环境接入（`.env`）

`AGENT_EVAL_HOST/API_KEY/UPLOAD`（平台上报）、`PLATFORM_*`（web/executor 基础设施）、`WORKSPACE_DIR`。仅此。

## 三、运行时数据与产物（workspace）

`workspace/` 是评测状态的单一聚集地——**清除 workspace 即获得全新重测环境**：

```
workspace/
├── runs/{run_id}/           # 一次运行的产物分层
│   ├── packages/{task_id}/  #   ExecutionPackage（manifest/task/trace/metrics + output/）
│   ├── agent_logs/          #   执行 Agent 决策日志（JSONL）
│   ├── results/{task}/      #   评估结果（report/rule_results/scores + evidence/）
│   └── reports/             #   汇总报告 + run_manifest
├── cache/                   # 评估缓存（键 = 内容指纹 + 规则集 + LLM 指纹）
├── packages/                # pack 命令的执行包输出
├── datasets/                # 本地数据集
└── sut_sessions/{sut}.json  # SUT 登录会话 token（0600，过期清理；跨 run 复用）
```

## 四、目录组织总览

```text
agent-eval-system/                        ← 仓库（内部仓即私有）
├── evaluator/agent_eval/assets/
│   ├── packages/{scenario}/{ver}/        ← 场景包：方法论+考卷+SUT 接入（§2.1；开源包 sut_configs/ 留空）
│   ├── examples/                         ← 配置模板（sut_config.example 等，占位符）
│   └── schemas/                          ← JSON Schema（公开契约）
│
├── .env                                  ← 仅环境接入（§2.5）
│
workspace/                                ← 运行状态（§三）
~/.agent_eval/                            ← 本机密钥区（0600）
├── llm.json                              ←   LLM 角色注册表（§2.3）
└── sut_credentials.json                  ←   SUT 凭证（§2.2）

平台 DB                                   ← 云端配置面
├── scenario_packages / *_assets          ←   场景包资产副本（importAssetsToDb 同步）
├── llm_models                            ←   LLM 配置（api_key 加密）
└── secrets                               ←   org 级凭证 KV（加密，§2.4）
```

双形态对称：

| | 本地 | 云端 |
|---|------|------|
| LLM 配置 | `~/.agent_eval/llm.json` | `/admin` 页面 |
| SUT 凭证 | `~/.agent_eval/sut_credentials.json` | org Secrets 页面 |
| 包资产 | 仓库 YAML 直读 | DB 副本拉取 |
| 环境接入 | `.env` | SCF env |

## 五、一次评测运行的数据流

```text
输入绑定                     运行                        输出与上报
─────────                   ────                        ─────────
场景包 ──────────────┐
 （考卷+SUT 接入）    ├→ 运行定义 ──→ 执行 Agent ──→ ExecutionPackage ──→ 评估器 ──→ 指标/报告
凭证（密钥区/Secrets）┤   （run_manifest      （驱动 SUT、     （workspace/runs/     （LLM Judge 用
LLM 配置 ────────────┘    记 package_ref        会话复用、        /packages/）         角色注册表）
suite.yaml（可选）         + llm 指纹）          预算控制）              ├→ 本地报告
                                                              └→ ResultSink → 平台
```

- **运行定义显式化**：`run_manifest` 记录 `{package_ref（含 task_set 与 SUT）, llm 指纹}` 与内容指纹；`Run.sutVersion` 从包内 SUT 解析填充
- **suite.yaml 声明式矩阵**：

```yaml
suite: sasan-agent-monthly
runs:
  - { package: chat@1.0 }                          # 缺省考卷 + 唯一 SUT
  - { package: chat@1.0, task_set: regression }
  - { package: chat@1.0, sut: sasan-agent@prod }   # 同包多环境
```

## 六、实施指引（现状 → 目标）

已实施：LLM 配置双形态（§2.3）。其余为目标态，按优先级：

| 优先级 | 实施项 | 内容与验收 |
|--------|--------|-----------|
| P0 | 包资产合并 | `workspace/{task_sets,sut_configs}/` 归位到对应包的 `task_sets/`、`sut_configs/`；manifest 增 `default_task_set`/`default_sut`；CLI `--package` 一参数解析全套；`TaskSetAsset` 随包同步 |
| P0 | SUT 凭证文件 + `secrets` 命令 | `~/.agent_eval/sut_credentials.json`（0600，通用 KV）；`secrets set/list/delete` 子命令；`CredentialStore` 增文件源（文件 → env 双通道） |
| P0 | 平台 Secrets | `secrets` 表（org 级 KV、AES 加密、写后不可读）+ org 设置页面 + `GET /api/public/secrets`（鉴权/审计）+ executor 启动注入 env |
| P0 | 会话目录迁移 | `~/.agent_eval/sut_sessions/` → `workspace/sut_sessions/`（0600 语义不变） |
| P0 | 运行绑定显式化 + suite | `run_manifest` 记 `package_ref` + llm 指纹；`Run.sutVersion` 填充；`agent-eval suite` 命令（矩阵展开 + 汇总对照） |
| P1 | 执行包归位 run_id | `run` 产物写 `runs/{run_id}/packages/{task_id}/`，manifest 登记；`--package-dir` 接受 run 目录 |
| P1 | SUTConfigAsset 表移除 | SUT 走包资产链路后，该预留表（无路由无消费方）删除（schema + 迁移） |
| P2 | 执行包内容指纹 / workspace 分区 | 缓存键恢复内容维度；根目录收敛为 `runs/ cache/ packages/ datasets/ sut_sessions/` |
| P3 | 远端数据地图 | Langfuse / 平台 / 本地各自承载的数据、保留期、导出方式成文 |

开源准备（届时执行，当前无需动作）：冷启动无历史仓库；内置包 `sut_configs/` 不进初始 commit；内网域名/registry 中性化；`samples/` 业务确认；gitleaks 扫描验证。
