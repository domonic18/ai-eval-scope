# 执行拆分与 Gateway 合并方案

> 状态:设计方案(待评审)
> 关联文档:[`12 第三方系统对接方案`](./12第三方系统对接方案.md)、[`09 Web 可观测平台架构设计`](./09Web可观测平台架构设计.md)、[`04 评估引擎设计`](./04评估引擎设计.md)

## 1. 背景与问题

当前 `gateway` 镜像同时承担两类职责:

1. **Web API**:对外暴露 `POST /v1/jobs`、`GET /v1/jobs/{id}`、`GET /v1/rule-sets` 等 REST 接口。
2. **评测执行**:内部 `WorkerLoop` 轮询 `gateway.jobs` 队列,调用 `agent_eval.orchestrator.eval_packages()` 执行评测。

部署到腾讯云 SCF Web 函数(API 网关触发)时,**最大执行时间被限制为 900 秒**。评测任务一旦超过该阈值即被强制中断,导致:

- 大单元的多页课件、含视觉渲染的复杂评估无法稳定完成;
- 网关函数本身既要保持 HTTP 长连接,又要做 CPU 密集型评估,职责耦合;
- 无法利用腾讯云 SCF **异步执行最长 24 小时**的执行能力。

## 2. 目标

1. 将评测执行拆分为独立镜像 `agent-eval-executor`,部署为腾讯云 SCF **事件函数(Job 镜像 + 异步执行)**,摆脱 900 秒限制。
2. 将 gateway 的 Web API 合并到现有 **Web 后端**(`web/backend`),统一接入层。
3. Web 后端接收评测请求后,通过 SCF `Invoke`(Event 异步)触发 executor;executor 完成后复用现有 `ResultSink` 回传结果到 Web。
4. executor **不持有对象存储凭据**:输入/制品均经 Web 签发的 presigned URL 流转。

## 3. 参考模式

[SasanLens](../../../proj_pingback/SasanLens) 已采用类似拆分:

- Web(Node/Express)生成任务并写入共享 DB;
- 手写 TC3-HMAC-SHA256 签名,调用 `scf.tencentapi.com/?Action=Invoke`;
- `InvocationType=Event` 为异步触发,Web 立即返回任务 ID;
- ETL 容器读取 `SCF_CUSTOM_CONTAINER_EVENT` 环境变量获取事件;
- 状态通过共享 MySQL 同步,无 HTTP 回调链路;
- **失败兜底为乐观模型**:容器启动即置 `running`,跑完才写终态,无 reaper。

本方案沿用同一模式,把 ETL 替换为评测执行(`eval_packages` + `ResultSink`)。

## 4. 目标架构

```text

    ▼

    │

    └── SCF Invoke Event(传 job_id + presigned GET URL)──┐
                                                          │
                                                          ▼
                    ┌──────────────────────────────────────────┐
                    │  agent-eval-executor                      │   腾讯云 SCF
                    │  (事件函数 + Job 镜像 + 异步执行)          │   timeout ≤ 24h
                    │  读 SCF_CUSTOM_CONTAINER_EVENT            │
                    │  经 presigned URL 下载输入(不持凭据)      │
                    │  eval_packages()                          │
                    │  ResultSink.flush                         │
                    └───────────────────┬──────────────────────┘
                                        │
                                        ▼
                  Web /api/public/ingest + /artifacts/url (Bearer API Key)
                  (制品亦经 Web 签发的 presigned PUT 直传对象存储)
                                        │
                                        ▼
                        共享 PostgreSQL
                       public.* (Web + eval_jobs)
```

### 4.1 关键决策

| 决策 | 说明 |
|------|------|
| 部署形态:**事件函数 + Job 镜像** | SCF「事件函数 + Job 镜像」,事件经 `SCF_CUSTOM_CONTAINER_EVENT` 注入,镜像不监听端口。24h 需开启「**异步执行**」开关——**创建函数时勾选,创建后锁死、不可修改**,只能重建。`timeout` 设 `86400`。 |
| 任务表由 Web 统一 owning | `public.eval_jobs` 由 Prisma 治理;gateway 的 SQL 迁移目录整体删除。 |
| **executor 不持对象存储凭据** | 输入经 Web 签发的短期 presigned GET URL 下载;制品经 `/api/public/artifacts/url` 签发的 presigned PUT 直传。executor 只与 Web 通信。 |
| 输入走对象存储 | SCF 事件体经 env 注入,单 env ≤128KB / 总 env ≤2MB,大单元 zip 塞不进事件,必须落对象存储。 |
| executor 一次性 | 每个 SCF 事件只执行一个 job,执行完即退出。 |
| 失败兜底:乐观模型(同 SasanLens) | executor 启动第一时间 `mark_running`,沿用现有 `run_job` 的 try/except 兜底 `mark_failed`;不实现 reaper。 |
| 本地开发用 worker 模式 | 无真实 SCF 时,executor 容器以 worker 模式轮询 `public.eval_jobs`;生产用 SCF Invoke。 |

## 6. 关键改动

### 6.1 数据库迁移治理合并

任务表由 Web 统一 owning。治理收敛到 `db/web/`(Prisma),删除 `db/gateway/`。

在 `db/web/prisma/schema.prisma` 新增 `EvalJob` model,置于 `public` schema:

```prisma
model EvalJob {
  id              String    @id @default(uuid()) @map("job_id")
  projectId       String    @map("project_id")
  orgId           String    @map("org_id")
  status          String    @default("queued")
  inputKind       String    @map("input_kind")
  scope           String
  inputObjectKey  String    @map("input_object_key")
  ruleSetId       String    @map("rule_set_id")
  apiKeyId        String    @map("api_key_id")
  runId           String?   @map("run_id")
  webRunUrl       String?   @map("web_run_url")
  scfRequestId    String?   @map("scf_request_id")
  taskId          String?   @map("task_id")
  taskTitle       String?   @map("task_title")
  taskSubject     String?   @map("task_subject")
  metrics         Json?     @db.JsonB
  error           Json?     @db.JsonB
  createdAt       DateTime  @default(now()) @map("created_at")
  startedAt       DateTime? @map("started_at")
  finishedAt      DateTime? @map("finished_at")

  @@index([status])
  @@index([projectId, createdAt])
  @@map("eval_jobs")
}
```

- `input_object_key`:Web 上传输入后写入,executor 经 presigned GET URL 下载。
- `scf_request_id`:Web 触发 SCF 后写入,便于链路追踪。

治理调整:

- 删除 `db/gateway/` 整个目录。
- `db/apply.sh` / `db/apply-prod.sh` 移除 gateway SQL 应用逻辑,仅执行 Prisma 迁移。
- executor Python 中的 SQLAlchemy model 重命名为 `EvalJob`,表名 `public.eval_jobs`,字段与 Prisma model 保持一致。
- 无存量数据兼容:新表直接创建,旧 `gateway.jobs` 不迁移。

### 6.2 Web 后端新增 eval 路由与输入物化

在 `web/backend/src/server.ts` 注册:

```typescript
app.use("/api/v1/jobs", evalJobsRouter)
app.use("/api/v1/rule-sets", evalRuleSetsRouter)
app.use("/api/v1/health", evalHealthRouter) // eval 子系统健康
```

`services/evalJob.service.ts` 提交流程:

1. `requireApiKey` 鉴权(复用 `middleware/apiKeyAuth.ts`,scope 含 `ingest`)。
2. 物化输入(multipart 文件 / JSON inline → Buffer),**在 Web 侧复刻 zip 探测/解压/scope 推导**(见下)。
3. `storage.put({ key: "projects/{project_id}/eval/jobs/{job_id}/input.{ext}", body, contentType })` 上传输入(key 沿用 `projects/{project_id}/...` 前缀,保持租户隔离约定)。
4. `storage.presignGet({ key, ttlSec: 3600 })` 签发**短期下载 URL**(1h,覆盖 SCF 冷启动 + 下载窗口)。
5. `evalJobRepository.create({ ..., inputObjectKey })` 写入 `public.eval_jobs`。
6. `scf.invoke({ job_id, rule_set_id, task_id, task_title, task_subject, input_kind, scope, input_object_key, input_presigned_url })`。
7. 返回 `202 { jobId, status: "queued", pollUrl: "/api/v1/jobs/{job_id}" }`。

**输入物化与 scope 推导(必须在 Web 侧复刻)**:现有 `gateway/eval_gateway/storage/workspace.py` 承载核心逻辑,删除 gateway 时不能丢,需用 TypeScript 复刻到 `web/backend/src/infra/inputMaterialize.ts`:

- zip 探测(`.zip` 后缀或 `PK` 魔数)→ 解压 → `scope = "unit"`;否则单文件写入 → `scope = "single"`。
- zip-slip 防护(`_is_safe_path` 路径穿越校验)。
- 解压上限 100MB、上传上限 50MB。
- 中文文件名编码修正(CP437 → UTF-8/GBK/GB18030,见 `_decode_zip_name`)。

### 6.3 rule-sets 目录(构建期静态化)

`/v1/rule-sets` 原本由 gateway 调用 Python 评估器 `CapabilityResolver` **实时派生**每个规则集的所需能力(LLM/视觉)。Web 是 TypeScript,无法调用 Python 评估器,故改为**构建期生成静态 catalog**:

- 新增 `scripts/gen_rule_sets.py`:在 evaluator 环境下运行,调用 `eval_gateway.rules.registry.catalog()`(或直接复用其逻辑),产出 `web/backend/assets/rule-sets.json`,**提交入库**。
- `web/backend/src/routes/eval/ruleSets.ts` 直接 `import` 该 JSON 返回,无需运行时 Python。
- CI(或 pre-commit)在规则集变更时重新生成,保证不漂移。
- executor 内部仍保留 `rules/registry.py`(用于规则集路径查找),但不再对外暴露 HTTP。

### 6.4 SCF Invoke 客户端与部署形态

`web/backend/src/infra/scf.ts` 参考 SasanLens `backend/src/tencentcloud.js`,手写 TC3-HMAC-SHA256 签名调用 `scf.tencentcloudapi.com`:

```typescript
export async function invokeScf(payload: ScfPayload): Promise<{ RequestId: string }>
```

配置项(加入 `web/backend/src/config/index.ts`):

- `TENCENT_SCF_ENABLED`(bool,本地 false)
- `TENCENT_SCF_REGION`、`TENCENT_SCF_NAMESPACE`、`TENCENT_SCF_FUNCTION_NAME`
- `TENCENT_SECRET_ID`、`TENCENT_SECRET_KEY`

> **SCF 函数侧(控制台 / Terraform 创建)硬性要求**:必须为「**事件函数 + Job 镜像**」;创建时勾选「**异步执行**」(创建后锁死、不可修改,只能重建函数);`timeout = 86400`;镜像即 `agent-eval-executor`。否则默认仍是 900s,且拿不到 24h。

| `api/routes/*.py` | 删除 | 路由迁到 Web |

`executor/executor/entrypoint.py` 支持两种模式:

```python
def main():
    setup_logging()
    event = _parse_event()  # SCF_CUSTOM_CONTAINER_EVENT 或 EVALEXECUTOR_JOB_JSON
    if not event:
        return _run_worker_mode()  # 本地开发:轮询 public.eval_jobs
    _run_single_job(event)
```

`_run_single_job`:

1. **第一时间** `mark_running(job_id)`(缩小卡死窗口)。
2. 经 event 里的 `input_presigned_url`,用 HTTP GET 下载输入 → `/tmp/executor-workspaces/{job_id}/input`(**不持对象存储凭据**)。
3. `build_package(...)` → `.../package`。
4. `eval_packages(...)`。
5. 按 `api_key_id` 解密 API Key,构造 per-job `ResultSink`,`sink.flush(...)`:
   - 事件 → Web `/api/public/ingest`;
   - 制品 → Web `/api/public/artifacts/url` 签发 presigned PUT 后**直传对象存储**(沿用现有 `_upload_artifact`,本就不持凭据)。
6. `mark_done(job_id, run_id, metrics, web_run_url)` 或(异常)`mark_failed(...)`。

## 7. 失败兜底

与 SasanLens ETL 一致,采用**乐观模型**:

- executor 启动后**第一时间** `mark_running`(在下载输入、初始化之前),缩小「SCF 已触发但状态仍 queued」的窗口。
- 沿用现有 `run_job` 的 `try/except`:评估过程的任意异常都走 `mark_failed`,不会静默卡在 running。
- **不实现 reaper / 定时收割**(与 SasanLens 一致)。代价:若 executor 进程在 `mark_failed` 之前被 OOM/回收(镜像拉取失败、实例被平台回收),任务会停在 running。由于评测任务可由调用方重新提交,且系统尚未大规模使用,接受此风险。
- 任务状态机:`queued`(Web 写)→ `running`(executor 启动写)→ `completed` / `failed`(executor 终态写)。

> 腾讯云异步执行函数**不支持平台重试**;DLQ 基于 CMQ 且仍处内测(需工单),不在本方案承诺范围内。

## 10. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| SCF 异步执行无平台重试 | 进程崩溃则任务卡死 | executor 启动即 `mark_running` + try/except `mark_failed`(§7);不做 reaper,接受极小概率残留。 |
| SCF 冷启动慢(镜像函数) | 首任务延迟高 | 生产配预置并发;presigned GET URL 时效设 1h 覆盖冷启动。 |
| presigned GET URL 过期 | executor 下载失败 | TTL 设 1h;必要时 executor 回调 Web 重新签发(可选)。 |
| 临时密钥 8–12h 过期 | 长任务访问 COS 失败 | executor 不持运行角色密钥,制品经 Web presigned PUT(由 Web 持久密钥签发),规避此问题。 |
| `PLATFORM_KEY_ENCRYPTION_KEY` 泄露 | 所有 token 可被解密 | SCF 函数最小权限;禁止日志打印 payload/env;定期轮换。 |
| 事件体 128KB/2MB 限制 | 大输入塞不进 event | 统一走对象存储 + presigned URL(本方案默认)。 |
| 本地开发与 SCF 行为差异 | 线上才暴露问题 | 本地用 worker 模式 + MinIO,保持代码路径一致;CI 增加 SCF 风格集成测试。 |
| 大文件上传 | 内存/超时 | Web 端限制 50MB;multipart 解析加 zip-slip/路径遍历防护。 |
| 异步执行开关创建后锁死 | 忘勾选则只能重建函数 | 部署模板(Terraform/SCF Component)在 create 阶段写死 `asyncRunEnable=true`。 |
