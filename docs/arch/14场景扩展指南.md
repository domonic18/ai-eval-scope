# 场景扩展指南 — 如何新增一个评估场景

> 本系统以「课件生成」为首个场景，但架构是**场景无关 + 数据驱动**的：聚合策略、指标定义、评估器集合全部来自场景包配置，不写死任何场景。本文以已内置的 **`code`（代码生成）** 场景为范例，说明如何新增一个全新场景并端到端跑通。
>
> 配套设计：[04 评估引擎设计](./04评估引擎设计.md)、[06 数据管理与配置规范](./06数据管理与配置规范.md)、[13 配置管理设计](./13配置管理设计.md)。

## 1. 核心概念

| 概念 | 说明 | 关键文件 |
|---|---|---|
| **场景包** (ScenarioPackage) | 一个场景的全部资产：规则集 + 提示词 + 数据集 + 指标策略，打包发布到 Web 配置中心，executor 运行时拉取 | `evaluator/agent_eval/assets/packages/<scenario>/<ver>/` |
| **ScenarioConfig** | 场景的聚合策略 (`AggregationPolicy`) + 指标定义 (`MetricDefinition[]`)，从包内 `metrics/policy.yaml` 加载，数据驱动（不 hardcode） | 包内 `metrics/policy.yaml` |
| **评估器注册表** | `@registry.register("xxx.yyy")` 装饰器注册的评估器类；规则集通过 `evaluator: xxx.yyy` 引用 | `evaluator/agent_eval/evaluation/evaluators/` |
| **entry_points** | 场景包声明「自己的评估器入口」（`manifest.entry_points.evaluators: "module:func"`）；加载包时导入该模块触发 `@registry.register`，使专属评估器随包可用 | 包 `agent_eval.yaml` + `evaluators/scenario/<name>.py` |

**两条路径**：
- 场景只用**内置评估器**（`format.*` 门控等）→ 不需要 entry_points，纯配置包即可。
- 场景需要**专属评估器**（如 `code.correctness`）→ 用 entry_points 把评估器代码随包声明加载。

## 2. 新增场景：以 `code` 为例（端到端）

`code` 场景：评估 SUT 生成的 Python 代码文件（`.py`）—— 格式门控（有效 .py）+ 代码正确性/风格 LLM Judge。完整实现见 `evaluator/agent_eval/assets/packages/code/1.0.0/` + `evaluator/agent_eval/evaluation/evaluators/scenario/code.py`。

### 2.1 包目录结构

```
evaluator/agent_eval/assets/packages/code/1.0.0/
├── agent_eval.yaml          # 包清单（manifest）
├── metrics/policy.yaml      # 聚合策略 + 指标定义（ScenarioConfig 来源）
├── rules/code-quality.yaml  # 规则集（format 门控 + 专属评估器）
├── prompts/code_correctness.yaml  # LLM Judge 提示词
├── prompts/code_style.yaml
└── datasets/.gitkeep        # 无参考知识库时占位（满足 package validate）
```

### 2.2 清单 `agent_eval.yaml`

```yaml
package:
  id: code              # 包 id（package_ref = scenario/package:label）
  scenario: code        # 场景 id
  version: 1.0.0
  name: 代码生成质量评估内置包
  description: ...
  author: builtin
  labels: [production, latest]
  # 关键：声明本包自带的评估器入口（module:func）；加载包时导入该模块
  entry_points:
    evaluators: "agent_eval.evaluation.evaluators.scenario.code:register"
  artifact_types: [code/*]
```

> 仅用内置评估器的场景可省略 `entry_points`。

### 2.3 指标策略 `metrics/policy.yaml`

```yaml
aggregation_policy:
  id: code-default
  scenario_id: code
  stage_weights:
    - stage_id: format
      weight: 1.0
      is_gate: true
    - stage_id: quality
      weight: 1.0
      is_gate: false
      id: quality                      # StageWeight.id → stage_metrics 键 + 表达式上下文变量
      evaluator_weights:
        code.correctness: 0.6
        code.style: 0.4
  normalize_to: [0.0, 1.0]

metric_definitions:
  - id: code:delivery_rate             # 指标 id（<scenario>:<name>），平台按此键存取
    name: 交付合格率
    expression: "count(format_gate) / total"   # safe_eval 表达式（count/mean/gated_mean 等）
    threshold: 0.9
    unit: ratio
    explain: { ... }                   # 前端展示用（title/rows）
  - id: code:reward
    expression: "mean(reward)"
    threshold: 0.7
    unit: score
```

- `expression` 经 `safe_eval` 求值（白名单函数 `count/mean/gated_mean` + 上下文变量 `format_gate`/`<stage_id>_gate`/`<StageWeight.id>`/`total`）。
- `metric_definitions` 同时落库为场景默认（`importAssetsToDb` 写 `defaults_assets`），前端 `useScenarioDefaults(scenarioId)` 据此渲染指标。

### 2.4 规则集 `rules/code-quality.yaml`

```yaml
version: "1.0"
scenario: code
dimensions: [{ id: functional, name: 功能性, weight: 1.0 }, { id: effectiveness, ... }]
cascade:
  - { stage: format, name: 格式门控, stop_on_fail: true }
  - { stage: quality, name: 质量评估, stop_on_fail: false }
rules:
  - id: FMT_001
    stage: format
    method: format                     # 内置确定性门控
    format_type: extension
    extensions: ["py"]                 # 文件类型白名单（/debug 据此限定可上传类型）
    evaluator: format.response_format
  - id: CODE_CORRECTNESS
    stage: quality
    method: llm                        # LLM Judge
    prompt_id: code_correctness
    evaluator: code.correctness        # 专属评估器（随包 entry_points 注册）
```

- `method: format` 的 `extensions` 同时被 executor 用于**文件收集**（`build_package` 按此收敛）+ `/debug` 的**上传类型限定**——单一事实源。

### 2.5 专属评估器 `evaluators/scenario/code.py`

```python
from agent_eval.core.types import ConstraintTier, EvalMethod
from agent_eval.evaluation.evaluators.quality_evaluators import BaseLLMJudgeEvaluator
from agent_eval.evaluation.registry import registry

@registry.register("code.correctness")
class CodeCorrectnessEvaluator(BaseLLMJudgeEvaluator):
    evaluator_id = "code.correctness"
    name = "代码正确性"
    tier = ConstraintTier.SOFT
    method = EvalMethod.LLM_JUDGE
    template_id = "code_correctness"

@registry.register("code.style")
class CodeStyleEvaluator(BaseLLMJudgeEvaluator):
    evaluator_id = "code.style"
    ...

def register() -> list[str]:
    """entry_points 入口（幂等）：模块导入时装饰器已完成注册；本函数供 manifest 'module:func' 调用。"""
    return ["code.correctness", "code.style"]
```

- 继承通用 `BaseLLMJudgeEvaluator`（prompt 驱动），仅声明 `evaluator_id/tier/template_id`。
- `register()` 是 entry_points `:func` 的幂等入口（模块导入即注册，重复加载安全）。

### 2.6 导入到 Web 配置中心

```bash
cd web/backend
# 从 .env 拼 PLATFORM_DATABASE_URL（见 scripts/db-apply.sh）
PACKAGE_DIR=<repo>/evaluator/agent_eval/assets/packages/code/1.0.0 \
PLATFORM_DATABASE_URL="$DB_URL" npx tsx scripts/importAssetsToDb.ts
```

- `importAssetsToDb.ts` 已**场景通用化**：`scenario_id/version/name` 从 manifest 读取（不 hardcode courseware）。
- 导入后：scenario 行 + defaults 资产（metric_definitions + policy）+ 包本体（`{manifest, files}`）+ 规则集/提示词。
- `/debug` 的场景选择器 + `useScenarioDefaults("code")` 即可读到。

### 2.7 端到端验证

```bash
# CLI（需把 SUT 产出打包为 ExecutionPackage：manifest.json + output/*.py + output/_manifest.json）
cd evaluator
uv run agent-eval eval --package-dir <pkg> --package code --rule-set code-quality
# 产出 code:delivery_rate / code:quality / code:reward（非 courseware:*）
```

或经 `/debug` 页面：选 `code` 场景 → `code-quality` 规则集 → 上传 `.py` → executor 跑完产出 `code:*` 指标 + 样本详情展示源文件。

## 3. 配置加载链路（运行时）

```
job.package_ref (code/code:production)
  → PackageManager.resolve_ref → ResolvedPackage{root}
  → rule_set = load(rules/code-quality.yaml)
  → _resolve_scenario_config(rule_set, scenario_package_dir=root)
      ├─ load_package_entry_points(root)        # 读 manifest.entry_points → 导入 code.py → 注册 code.*
      └─ load_scenario_config_from_package(root) # 读 metrics/policy.yaml → ScenarioConfig(code:*)
  → build_pipeline(rule_set, scenario_package_dir=root)
  → evaluate: 评估器按 rule.evaluator 名从 registry 取实例（code.* 已注册）
```

**关键**：场景包根（含 `metrics/policy.yaml` + `agent_eval.yaml`）经 `rule_set_path.parent.parent` 推导（`rules/<name>.yaml` 的上上层），透传到 `_resolve_scenario_config`。

## 4. 参考实现（code 场景文件清单）

| 文件 | 作用 |
|---|---|
| `assets/packages/code/1.0.0/agent_eval.yaml` | 清单 + entry_points 声明 |
| `assets/packages/code/1.0.0/metrics/policy.yaml` | 聚合策略 + code:* 指标定义 |
| `assets/packages/code/1.0.0/rules/code-quality.yaml` | format 门控 + code.correctness/style |
| `assets/packages/code/1.0.0/prompts/code_*.yaml` | LLM Judge 提示词 |
| `evaluation/evaluators/scenario/code.py` | 专属评估器 + register() |
| `evaluation/evaluators/plugins/__init__.py` | `load_package_entry_points`（entry_points 通电） |
| `evaluation/scenario/defaults.py` | `load_scenario_config_from_package`（policy.yaml → ScenarioConfig） |
| `evaluation/engine.py` | `_resolve_scenario_config`（数据驱动 config 解析） |

**另一参考实现：`chat` 场景（对话型 SUT，v4.6.4）**——结构同 code 包
（`assets/packages/chat/1.0.0/` + `evaluation/evaluators/scenario/chat.py`）。差异要点：

- **评估对象是回答文本而非产物文件**：ExecutionAgent 把 SUT 回答物化为 `output/answer.md`
  （`agent/execution_agent.py _ensure_answer_file`，已有产物文件时不覆盖），评估器按文件收集的
  既有约定零改动复用。
- **三层规则**：`format.response_format`（extensions: [md]，门控非空回答）+ `chat.answer_exact`
  （HARD_SCORE，`expected.answer` 词边界精确匹配，未声明则 SKIP）+ `chat.answer_quality`
  （LLM Judge 三维度：正确性/切题性/完整性，prompt 注入 `instruction`/`must_mention`）。
- **expected 进评估上下文**：`engine._build_context` 现将 `task_data.expected` 放入
  `context["task_expected"]`（此前只有 `task_input`，expected 对照类评估器拿不到）。
- 指标：`chat:delivery_rate`（门控通过率，阈值 0.9）/ `chat:quality`（exact 0.4 + LLM 0.6）/
  `chat:reward`（综合，阈值 0.7）。

## 5. 常见问题

- **新场景产出 courseware:* 指标？** → `_resolve_scenario_config` 没拿到场景包根（`scenario_package_dir=None`），回退 courseware。检查 `eval_packages`/CLI 是否从 `rule_set_path` 推导了 `scenario_package_dir`。
- **`未找到 Prompt 模板`？** → JudgeOrchestrator 默认加载 courseware prompts；需传 `prompts_dir=<场景包>/prompts`（`eval_packages`/CLI 已自动从 `scenario_package_dir` 推导）。
- **上传文件被拒/内容为空？** → 规则集 `format` 门控的 `extensions` 决定可上传类型 + executor 文件收集 + 文本读取，三者同源；确保新场景的 `extensions` 正确。
