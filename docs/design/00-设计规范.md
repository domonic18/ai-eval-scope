# EvalScope — Web 可观测平台 交互 UI 设计规范

> 版本 v2.0 · 2026-06 · 适用于 `web/frontend` shadcn/ui + Tailwind CSS v4 + Recharts 重构后
> 前端技术栈：React 18 + Vite + TypeScript + shadcn/ui（Radix 基础）+ Tailwind CSS v4 + Recharts；旧 Ant Design / ECharts / 自研 CSS 已移除

---

## 1. 设计目标与问题回应

本次设计针对反馈的两个核心问题：

| 反馈问题 | 设计对策 |
|---------|---------|
| **① 交互不符合行业最佳实践**，与 langfuse 差距大（创建项目 / 配置 API Key / 查看项目数据 / 运行详情 / 报告摘要 / 评估细则 / 原始文档预览） | 重构信息架构为 **组织 → 项目 → 运行 → 样本 → 约束** 五级钻取（drill-down）层级；每一级都有清晰的概览→明细路径；API Key 接入做成「签发即给接入代码片段」的引导式流程；文档预览改为 **左右分栏（结论 ↔ 原文）** 对照视图。 |
| **② 视觉难看**，缺风格 / 配色 / Logo | 建立完整设计系统（暗色仪器风 / 统一色板 / Inter + JetBrains Mono 双字体 / EvalScope reticle logo）；所有数据用等宽字体对齐，强化「测量仪表」观感。 |

### 品牌定位

- **品牌名**：EvalScope
- **一句话**：Agent 能力的「示波器」—— 把每一次评估运行的信号、约束与证据，量化、对照、可追溯。
- **调性**：科技 / 冷静 / 仪器级（instrument-grade）。克制的动效，数据优先，等宽字体承载所有量化信息。刻意避免渐变滥用、emoji、圆角卡通感等「AI 生成味」。
- **Logo 含义**：圆环 = 镜头/示波范围（scope），十字刻度 = 测量基准（reticle），上扬折线锁定到青色靶点 = 评估信号收敛到目标。

## 2. 信息架构（IA）

```
EvalScope
│
├─ 公开区
│   ├─ 登录 /login
│   ├─ 注册 /register（注册即创建/加入组织）
│   └─ 加入组织 /join（申请+审批流程）
│
└─ 应用区（左侧固定导航 = 组织上下文，结构固定不变）
    ├─ 主导航（固定）：项目看板 /dashboard / 全部运行 /runs
    ├─ 组织分区（固定）：成员 / 组织设置
    │
    ├─ 项目看板 /dashboard          ← 组织下所有项目卡片 + 关键指标
    │   └─ 新建项目（Dialog）
    │
    ├─ 项目详情 /project/:id        ← 单项目
    │   ├─ 概览 Tab：趋势图 + 运行列表（指标含 Tooltip 说明）
    │   ├─ 运行 Tab：可筛选的运行表
    │   └─ 设置 Tab（子导航四面板）：
    │       ├─ API Key：新建 / 删除（删除即移除，无残留）+ 一次性密钥 + 接入代码
    │       ├─ 基本信息：名称 / slug / 描述 / 默认规则集
    │       ├─ 数据保留：运行样本保留期 + 制品保留期
    │       └─ 危险区：归档项目 / 删除项目（输入 slug 确认）
    │
    ├─ 运行详情 /run/:id            ← 单次评估运行
    │   ├─ 指标卡（DR / CPR / Reward / CondR，含阈值对照 + Tooltip 指标说明）
    │   ├─ 失败分布（按约束）
    │   ├─ 报告摘要（Markdown 渲染 + 下载）
    │   └─ 样本列表（可按状态/分数筛选、排序）
    │
    └─ 样本详情 /run/:id/sample/:sid   ← 单个被评估文档（左右分栏）
        ├─ 左：分阶段约束结论（format / commonsense / quality）
        │      阶段得分 S_format/S_common/S_soft/S_pref 均带 Tooltip 说明
        └─ 右：原始文档 / 渲染截图 预览（Tab 切换 + 同步定位）

平台超级管理员后台（独立 shell，/admin/*，platformAdmin 专属）
├─ /admin              概览统计
├─ /admin/users        用户管理
├─ /admin/orgs         组织/团队管理
├─ /admin/projects     项目管理
├─ /admin/runs         运行管理
├─ /admin/artifacts    产出物管理
└─ /admin/audit        审计日志
```

### 导航与面包屑

- 左侧边栏结构**固定不变**：`主导航（项目看板 / 全部运行）` + `组织分区（成员 / 组织设置）`。
- **废弃随页面变化的「当前项目」动态子菜单**——旧版在不同页切换会改变侧栏内容，易让用户对导航产生不确定感。项目级操作统一收纳进「项目详情」页内的 Tab/子导航。
- 顶栏始终显示**面包屑**：`组织 / 项目 / 运行 #id / 样本 task_id`，任意一级可点击回跳。
- 钻取关系唯一且可逆，杜绝「迷路」。

### 指标可解释性（Tooltip 说明组件）

- 非直观指标（DR / CPR / Reward / CondR / S_format / S_common / S_soft / S_pref）旁配 `?` 图标按钮，点击/悬停弹出 Tooltip，含**定义 / 计算方法 / 评估标准**三段式。
- 实现：基于 shadcn `Tooltip` 封装 `Explain` 组件（`src/components/shared.tsx` 或独立组件），保持触发器与内容解耦，支持键盘聚焦与 `prefers-reduced-motion`。

## 3. 核心用户流程

### 流程 A：首次接入（onboarding）
```
注册账号 → 自动创建默认组织 → 新建项目（名称+slug）
   → 进入项目设置 → 签发 API Key
   → 复制接入代码片段（环境变量 + ResultSink 配置）
   → 评估器侧运行 → 数据经 HMAC 摄取 → 看板出现首个运行
```
关键体验点：**签发 Key 的弹窗直接给出可复制的接入代码**，而不是只丢一串密钥让用户自己查文档。

### 流程 B：日常巡检（最高频）
```
项目看板（一眼看哪个项目指标掉了）
   → 项目详情看趋势（哪次运行回归）
   → 运行详情看失败分布（哪类约束失败最多）
   → 样本详情看具体结论 + 对照原文（为什么失败）
```
每一步都从「聚合」自然下钻到「个体」，符合 overview-first / details-on-demand 原则。

### 流程 C：定位一次失败
```
运行详情 → 失败分布点击某约束（如 format.document_count）
   → 自动筛出该约束失败的样本
   → 进入样本 → 该约束已高亮展开 → 右侧定位原文证据
```

## 4. 设计系统（Design Tokens）

完整实现见 `web/frontend/src/styles/globals.css`。采用 Tailwind CSS v4 `@theme inline` 与 CSS 变量，暗色为唯一默认主题（`<html class="dark">`）。

### 4.1 色板

| 角色 | CSS 变量 | oklch 值 | 用途 |
|------|------|----|----|
| 背景（底） | `--background` | `oklch(0.16 0.012 260)` | 页面底色 |
| 背景（抬升） | `--card` | `oklch(0.19 0.014 260)` | 卡片 |
| 背景（表面） | `--secondary` / `--input` | `oklch(0.24 0.014 260)` | 输入框 / 次表面 |
| 描边 | `--border` | `oklch(0.28 0.014 260)` | 分隔线 |
| 主文字 | `--foreground` | `oklch(0.95 0.005 260)` | |
| 次文字 | `--muted-foreground` | `oklch(0.68 0.012 260)` | 元信息 |
| **品牌主色** | `--primary` / `--chart-1` | `oklch(0.62 0.19 264)` | 电光蓝，操作/选中/趋势主色 |
| **信号色** | `--chart-2` | `oklch(0.78 0.13 175)` | 青，数据可视化第二色 |
| 成功 | `--success` / `--chart-5` | `oklch(0.7 0.16 145)` | PASS |
| 警告 | `--warning` / `--chart-3` | `oklch(0.7 0.16 70)` | soft tier |
| 危险 | `--danger` / `--destructive` | `oklch(0.62 0.21 25)` | FAIL / hard tier |
| 信息 | `--info` | `oklch(0.7 0.13 240)` | preference tier |

> 配色原则：底色冷而深，仅用主色 + 信号色两种品牌色，语义色仅在状态处出现。避免大面积彩色，量化数据靠等宽字体而非颜色取胜。

### 4.2 约束层级（Tier）语义色

| Tier | 含义 | 颜色 | 失败影响 |
|------|------|------|---------|
| `hard_gate` | 格式硬门禁，失败即 fail-fast，后续阶段 SKIP | 红 `text-destructive` / `bg-destructive/10` | `S_format = -3` |
| `hard_score` | 常识硬约束，不中断但标记 gate 未过 | 红 `text-destructive` / `bg-destructive/10` | `S_common = 0` |
| `soft` | 软约束，加权平均 | 黄 `text-chart-3` / `bg-chart-3/10` | 计入 `S_soft` |
| `preference` | 偏好约束，加权平均 | 蓝 `text-info` / `bg-info/10` | 计入 `S_pref` |

### 4.3 字体

- **界面字体**：Inter（400/500/600/700/800）—— 字重区分层级。Tailwind 中通过 `font-sans` 使用。
- **数据字体**：JetBrains Mono —— 所有数字、ID、指标、代码。等宽对齐是「仪器感」的关键。Tailwind 中通过 `font-mono` 使用。
- 字号阶：以 Tailwind 默认 scale 为基，正文 `text-sm`，指标值 `text-2xl/text-3xl`，元信息 `text-xs`。

### 4.4 圆角 / 阴影 / 动效
- 圆角：以 `--radius: 0.625rem`（10px）为基准，shadcn 组件默认 `rounded-md`；卡片用 `rounded-lg`，弹窗用 `rounded-xl`。
- 阴影仅用于浮层（弹窗 / 下拉 / hover 抬升），平面区域无阴影。
- 动效统一 `transition-colors duration-150 ease-in-out`，仅做 hover/选中/展开，不做装饰性动画。
- **入场编排**：页面容器使用 Tailwind 工具类做错落淡入（如 `animate-in fade-in slide-in-from-bottom-2 duration-300`）；`prefers-reduced-motion` 下自动关闭。
- **Live 信号**：`running` 状态点用 `animate-pulse` + 主色光晕，呼应「实时摄取」。
- 氛围层（`pointer-events-none`）：
  - 顶部蓝光 + 右下青光径向渐变；
  - 衰减网格（仪表台）；
  - 极低强度 CRT 扫描线，把「Scope/示波」概念落到每一个界面表面。

### 4.5 数字排版（仪器读数细节）
- 所有等宽数字（`font-mono` / `tabular-nums`）统一启用 `font-variant-numeric: tabular-nums`，保证逐列对齐、刷新不跳动——这是「测量仪表」观感成立的关键细节。
- 指标卡 `hover` 时顶边点亮一道信号高光（`bg-gradient-to-r from-primary/50 to-signal/50`），暗示读数「通电」。

## 6. 各页面设计要点

### 6.1 登录 / 注册 / 加入组织
- 居中卡片 + 氛围光。登录支持密码；注册引导填写「组织名称」，落地即有租户上下文。错误态、一次性提示均使用 `Alert` + `sonner`。

### 6.2 项目看板 `/dashboard`
- 组织下项目卡片网格（`shadcn/card.tsx`）。每卡：项目名 + slug + 最新运行的 DR/Reward + 运行数 + 迷你趋势火花线（`components/Sparkline.tsx`）+ 最近运行时间 + 状态。空态引导新建。右上「新建项目」弹窗。

### 6.3 项目详情 `/project/:id`
- **概览**：DR/CPR/Reward/CondR 趋势折线（Recharts，可切指标/周期）+ 最近运行列表。
- **运行**：完整运行表，按模式/规则集版本/时间筛选，分页。
- **设置**：基本信息编辑；**API Key 管理**（列表含公钥/调用次数/最近使用/状态/吊销；签发弹窗含一次性密钥 + 接入代码片段 + 环境变量说明）；数据保留天数；归档（危险区）。

### 6.4 运行详情 `/run/:id`
- 顶部：运行号 + 状态 + 模式 + 规则集版本 + Langfuse 链接 + 下载报告。
- 四张指标卡含**阈值对照**（gauge 标出阈值线，达标/未达标着色）。
- **失败分布**：按约束的失败次数条形榜，可点击下钻筛样本。
- **报告摘要**：Markdown 渲染区 + 下载 JSON/MD。
- **样本表**：task_id / 状态 / Reward / 各阶段分数，可筛可排序，点击进样本。

### 6.5 样本详情 `/run/:id/sample/:sid`（核心创新）
**左右分栏对照**：
- 左栏：按阶段分组（格式 / 常识 / 质量）的约束结论。每条：tier badge + PASS/FAIL badge + 名称 + 分数 + 原因；展开看 details/moduleResults/Judge 出处。失败项默认展开并锚点高亮。
- 右栏：原始文档预览（HTML iframe / Markdown / 文本）+ 渲染截图 Tab；顶部可切换制品。
- 设计意图：**「结论」与「证据」并置**，让用户无需来回跳转即可判断结论是否成立——这是评估平台区别于普通 BI 的关键。

### 6.6 超管后台 `/admin/*`
- 独立 `AdminLayout`，深色仪表风；左侧为管理导航，顶部显示平台级面包屑。
- 用户/组织/项目/运行/产出物/审计均使用数据表 + 详情抽屉/弹窗；危险操作（删除/禁用）需二次确认。

## 7. 可访问性与响应式
- 对比度：主文字/背景 ≥ 12:1，次文字 ≥ 4.5:1（oklch 取值已按 WCAG 校准）。
- 所有可点元素有 hover/focus 态；表单 focus 有 3px `--ring` 光圈。
- shadcn 组件默认支持键盘导航与 ARIA；自定义组件需保留 `role`、`aria-label`、`aria-expanded` 等属性。
- ≤920px 收起侧边栏（移动端以查看为主，编辑操作降级）。
- 颜色不作为唯一信息载体：PASS/FAIL 同时有文字与图标。

## 8. 落地建议（与现有技术栈对接）

当前前端已完成向 **shadcn/ui + Tailwind CSS v4 + Recharts** 的重构，旧 Ant Design、ECharts、自研 `theme.css` / `pages.css` / `components/ui/*` 已全部移除。新增 UI 按以下规范执行：

1. **新增基础组件优先走 shadcn CLI**：`npx shadcn add <component>` 会按 `components.json` 生成到 `src/components/shadcn/`（别名 `@/components/shadcn/*`），保持 New York 风格与 CSS 变量主题。
2. **样式一律用 Tailwind 工具类**：禁止新建自定义 CSS 文件。需要全局 token 时在 `src/styles/globals.css` 的 `@theme inline` 中扩展；需要动画使用 `tw-animate-css`。
3. **色彩必须使用 CSS 变量**：业务代码中写 `bg-primary text-primary-foreground border-border` 等，不要硬编码色值。语义别名 `--success` / `--warning` / `--danger` / `--info` / `--signal` 可在 `dark` 作用域下引用。
4. **字体**：界面文字 `font-sans`（Inter），数字/代码/ID `font-mono`（JetBrains Mono）并加 `tabular-nums`。
5. **图表**：趋势/分布统一用 Recharts，主题色取自 `--chart-1`（电蓝）与 `--chart-2`（信号青）；复杂图表可复用 `components/shadcn/chart.tsx` 的 ChartContainer/ChartTooltip 封装。
6. **图标**：使用 `lucide-react`（已在 `components.json` 中配置为图标库），图标尺寸默认 16px（`size-4`），按钮内与文字对齐。
7. **反馈**：操作成功/失败/复制使用 `sonner` Toast（`useToast` / `toast.success()` / `toast.error()`）；常驻提示用 `shadcn/alert.tsx`。
8. **代码质量**：提交前执行 `npm run lint && npm run build`；类型严格，禁用 `any`；组件保持 300 行以内，过长则拆分。
