接入指南

更新于 2026-09-22 · 适用于 v0.4+

准备工作

所有接入通道共用以下准备步骤：

  1. 创建项目 — 登录控制台 → 项目看板 → 新建项目（名称 + slug）。
  2. 签发 API Key — 进入项目 →「设置 & API Key」→ 新建。Key 形如 eval-…，仅创建时明文展示一次。
  3. 确认平台地址 — 本地 docker-compose 默认 http://localhost:9000。
统一鉴权：所有通道均使用 Authorization: Bearer <api_key>；项目归属完全由 Key 决定，提交时无需（也不接受）project_id。

通道一 · HTTP API

服务端系统对接的主力方式：REST 提交评测任务，轮询结果或取速览。

http — 提交与轮询
# 1) 提交评测任务 → 202 Accepted
$ curl -X POST https://eval.example.com/api/v1/jobs \
-H "Authorization: Bearer eval-…" \
-F "file=@sasan-edu-function.zip"
{"job_id": "0bc0b717-…", "status": "pending"}

# 2) 轮询结果（任务完成后返回指标与结论）
$ curl https://eval.example.com/api/v1/jobs/0bc0b717-… \
-H "Authorization: Bearer eval-…"
{ "status": "completed", "metrics": { "edu:document_rate": 0.962, … } }

提交支持三种内容形态：JSON 内联（application/json）、原始字节上传（application/octet-stream）、大文件直传（>50MB 走 presigned PUT）。不想轮询可在任务提交后直接取速览：

GET /api/v1/jobs/{id}/overview 返回指标与结论摘要，适合在业务页面直接渲染评估结果。

通道二 · Webhook 结果回调

评估完成（completed / failed）后平台主动 POST 你的服务，免去轮询。

  • 项目级配置 — 项目设置中填 webhookUrl（生产强制 HTTPS），对该项目下所有 job 生效。
  • 签名校验 — 请求携带 X-Webhook-Signature 头；签名密钥 AES 加密存储、不回显。
  • 可靠性 — 投递失败自动重试；即便不配 Webhook 也随时可回退轮询兜底。

通道三 · MCP 接入（智能体）

把评测挂成 MCP 工具，让 Claude Code / Cursor 等智能体在对话中直接提交与查询评测。客户端配置：

mcp.json
{
  "mcpServers": {
    "evalscope": { "url": "https://eval.example.com/api/v1/mcp" }
  }
}

挂载后可用两个工具：list_packages 发现可用的场景包，submit_eval_job 提交评测任务（package_ref 必填）。

通道四 · CLI 直跑

评估器命令行直跑，结果经摄取链路自动回传平台；网络失败入离线队列，联网后重放。评估器侧 .env 配置：

变量说明
AGENT_EVAL_HOST平台地址，默认 http://localhost:9000
AGENT_EVAL_API_KEY项目 API Key（eval-…）
AGENT_EVAL_UPLOAD设为 true 开启摄取（需显式开启）
terminal
$ agent-eval pipeline --package sasan-edu-function --task "safety_*" --upload
✓ 评估完成，结果已上报可观测平台
