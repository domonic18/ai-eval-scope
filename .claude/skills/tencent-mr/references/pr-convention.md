# MR 标题与描述规范

## 标题格式

```
type(scope): 简要描述
```

### type 取值

| type | 含义 |
|------|------|
| feat | 新功能 |
| fix | Bug 修复 |
| refactor | 重构（不改变外部行为） |
| docs | 文档更新 |
| test | 测试相关 |
| chore | 构建/工具/依赖变更 |
| perf | 性能优化 |

### scope

模块或功能范围，如 `auth`、`api`、`report`、`ui`。可选，单模块项目可省略。

### 示例

```
feat(report): 周报工作项增加项目名称标识
fix(auth): 修复 Token 过期未自动刷新的问题
refactor(api): 重构数据查询层，统一 Git 和 TAPD 数据结构
```

## 描述模板

```markdown
## 变更概述
- 要点 1
- 要点 2
- 要点 3

## 测试说明
- 测试步骤 1
- 测试步骤 2
```

### 生成规则

1. **变更概述**：从 `git log target_branch..HEAD` 的 commit 历史中归纳，去重合并同类变更
2. **测试说明**：根据变更类型推断验证方式，如"运行 pytest"或"启动前端验证页面渲染"
3. **简洁**：描述控制在 5-10 行以内，避免堆砌每个 commit
4. **语言**：使用中文
